### FF-11 · Tighten output schemas, one procedure at a time

**Size: L** · **Blocked by: FF-1**

Replace `looseEnvelope` with real schemas — **one procedure per sitting, each
with a test that asserts the real payload survives.**

Derive them, don't hand-write them: `drizzle-zod@0.8.3` is current and compatible
with `drizzle-orm` 0.39.x, and `createSelectSchema(table)` is documented for
exactly this. Two caveats: import from the standalone `drizzle-zod` package (the
docs page now shows the 1.0 RC path), and `timestamp()` maps to `z.date()` — use
the refinement parameter (`createSelectSchema(t, { createdAt: z.iso.datetime() })`)
to keep `format: date-time`.

⚠️ Derive, then `.extend()`. A handler returning joined or computed fields will
have them **silently dropped** by a bare `createSelectSchema`.

### FF-12 · Fix the analytics empty states

**Size: M** · **Blocked by: nothing**

Four visible defects, three distinct causes.

**12a — the 100% bar on zero responses (guard bug, in SQL).**
`analytics.service.ts:77-80`: `WHEN prev_count IS NULL THEN 100.0`. `prev_count`
is `LAG(...)`, so it is always NULL for the first field — which reports 100%
retention over zero people.

```sql
WHEN prev_count IS NULL THEN CASE WHEN response_count > 0 THEN 100.0 ELSE NULL END
```

**Same expression, second bug:** `NULLIF(prev_count, 0)` makes `retention_pct`
NULL for every field after an unanswered one. That NULL flows into
`getFormStats:364-368`, where `null / 100 === 0` in JS, so each one contributes a
**100% drop-off** to `avgDropoffRate` — which carries 20% weight in the health
score. Invisible today, confusing later.

**12b — the `105%` axis tick (chart-domain bug).**
`AnalyticsComponents.tsx:125`: `domain={[0, 105]}`, padded so the right-hand bar
label doesn't clip. `margin.right` already reserves 48px. Use
`domain={[0, 100]} ticks={[0, 25, 50, 75, 100]}`.

**12c — the same sentence twice on one screen (layering bug).**
`analytics.service.ts:165-171` — when the health score is null, the *insight
generator* returns an insight whose text belongs to the health-score panel. Return
`[]` instead and let `InsightCards` show its own empty state.

Two consequences worth fixing while there: `InsightCards`' own empty message
(`AnalyticsComponents.tsx:365`) is **dead code** — `generateFormInsightsSummary`
can never return an empty array. And the service emits `icon: 'bar-chart-2'`
(`:167`, `:224`), which is not a key in `INSIGHT_ICONS` (`:343-350`), so it
silently falls back to `Info`. Type `FormInsight['icon']` as a union of the six
real keys.

**12d — the 0–4 axis on `FIELD RESPONSE COUNTS` (the same guard bug again).**
`AnalyticsComponents.tsx:424` and `:114` both guard `data.length === 0`, but
`data` is one row **per field**, not per response. One field with zero responses
passes the guard. Both guards ask "do we have fields?" when the question is "do
we have responses?":

```tsx
const hasResponses = data.some(r => Number(r.response_count) > 0);
```
